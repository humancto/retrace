Evidence

Five screens from one indexed video and one live frame: OpenCV's public vtest.avi, 80 s of a courtyard and about 10 people. The screens are not staged or cropped.

Method

This is the design of the cloud camera vendors on one laptop, with open weights. Retrace detects at a low frame rate, tracks, embeds the best crops, indexes them, and does an exact search.

camera · file · RTSP · HLS · YouTube Live
   └─ ffmpeg (4 fps, 640 px)
       └─ DEIM-D-FINE detector (ONNX, Apache-2.0)
           └─ sparse-fps tracker → one tracklet per visit: path, dwell, entry/exit edge, direction
               ├─ best 3 crops + context frame → SigLIP 2 / CLIP / EmbeddingGemma 2 → sqlite-vec
               ├─ (optional) local VLM caption → FTS5 → fused with the vectors by reciprocal rank
               └─ rules evaluate here, while the track is still open

question → rewrite → text tower → filtered exact KNN → threshold per query → clip cut from the recording

A low frame rate, on purpose

Four frames in each second are sufficient to know who came, where they went, and how long they stayed. Between two frames, a person who walks moves almost one box width. The tracker predicts with constant velocity, gates on IoU or centre distance, and confirms a track after 2 hits. On real video this made 35 visits from 136 fragments.

One file, exact search

The tracklets, the vectors, and the captions are in one SQLite database with sqlite-vec and FTS5. The search is an exact cosine scan over the filtered candidates. The threshold comes from the score distribution of the query. "a bicycle" returns 1 result and "a person" returns 30.

Images, sound, and words

With EmbeddingGemma 2 in the binary (llama.cpp, no Python), text, images, and 10 s audio windows share one space. On 2026-10-14, "a person in a red jacket", "una persona con chaqueta roja" and "ఎర్ర జాకెట్ వేసుకున్న వ్యక్తి" returned the same two people in red, with no translation step.

A Linux container with 2 cores answers the same searches in 50 to 65 ms. It keeps up with 4 cameras because it analyses each fourth to sixth frame. Backpressure skips frames. It does not queue them.

Get started

One binary, one database file, one HTML page. The first build compiles the onnxruntime bindings and takes some minutes. The first run downloads the open weights one time.

# macOS (Apple Silicon) or Linux · Rust 1.88+ · ffmpeg
$ brew install ffmpeg rust
$ git clone https://github.com/humancto/retrace && cd retrace
$ cargo build --release
$ scripts/e2e.sh                 # sample video → index → search → clip → eval

# your video
$ ./target/release/retrace --embedder siglip2-b16-256 ingest --source ~/Movies/driveway.mp4 --cam driveway
$ ./target/release/retrace --embedder siglip2-b16-256 serve
$ open http://127.0.0.1:8080/

# live cameras, while the server runs
$ ./target/release/retrace --embedder siglip2-b16-256 serve --source door=rtsp://user:pass@192.168.1.40:554/stream

Nothing leaves the machine

No account, no telemetry, no update check. The only outbound calls are the one-time weight downloads and the sources that you give. Use --models-dir on a computer with no network.

Open weights, open code

DEIM / D-FINE, CLIP, SigLIP 2, and EmbeddingGemma 2 are Apache-2.0 or MIT. Retrace is MIT. One flag changes the detector or the embedder.

Everything is an API call

Search, tracklets, clips, thumbnails, rules, alerts, events, and a live SSE feed are JSON over localhost. The UI is one HTML file. It uses only functions that the API exposes.
